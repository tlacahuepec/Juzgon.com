# Juzgon app audit: 2026-09-13

This audit records the current Windows working tree on `feature/issue-243-backup-coverage`, based on commit `c4827f0` plus the uncommitted image, backup, ranking, Settings, and enrichment changes. It supersedes the implementation-status claims in [the earlier analysis](../system_analysis_and_improvement_plan.md); that document remains useful for longer-term ideas.

The face-type feature is committed. Room v19, ZIP import/export, and the other working-tree changes are present but should not yet be treated as release-ready. The findings below distinguish reproduced defects, source inspection, and missing runtime verification. GitHub issue/PR status was not refreshed during this pass.

## Fixes made in this continuation

1. **Image replacements of the same byte length were silently discarded.** The repository's no-op check compared byte counts and a subset of metadata. It now compares byte contents and every stored metadata field, independent of image list order. A fresh array with identical content still avoids changing the item's update timestamp.
   - Code: [RoomRatingRepositories.kt](../../app/src/main/java/com/juzgon/data/repository/RoomRatingRepositories.kt), `hasSameImages`.
   - Regression: `RoomRatingRepositoryTest.saveRatedItem_updatesImageBytesAndMetadataButSkipsIdenticalContent` failed against the previous implementation. It covers changed bytes, changed dimensions/timestamp, and an unchanged save.
2. **Image-only items lost category context in backups.** The serializer only looked at ratings and values. It now also resolves category context from image attributes, allowing short image attribute IDs to normalize correctly during restore.
   - Code: [JsonBackupSerializer.kt](../../app/src/main/java/com/juzgon/data/backup/JsonBackupSerializer.kt), `serializeItems`.
   - Regression: `JsonBackupServiceTest.importArchive_roundTripPreservesCategoryForImageOnlyItem` failed with an empty exported category before the fix. It checks both the archive payload and restored category-scoped attribute ID.

## Existing fixes confirmed in source

These changes predate this continuation and remain uncommitted:

- Category rename moves score profiles to the new category before deleting the old category. `renameCategory_renamingCategoryNamePreservesScoreProfiles` covers this case.
- Ranking SQL includes value/image associations instead of requiring numeric ratings. `observeRankedItems_includesItemsWithOnlyDateAttributes` covers date scoring. This does **not** establish visibility for every unrankable category: `RoomRatedItemRepository.observeRankedItems` still returns an empty list when there are no rankable attributes.
- Item rename transfers image entities before deleting the original item. Existing rename coverage primarily checks ratings, legacy URI values, and snapshots; add a dedicated binary-image rename regression.
- Item edit/detail byte-array previews now calculate decode sample sizes. The earlier report's claim that these paths always decode at full resolution is stale.
- Settings exposes an import picker and replacement confirmation. Archive import reads `manifest.json` and `data.json`, verifies supplied checksums, and restores categories, items, profiles, and images inside the injected transaction. It is no longer an unavailable stub, but validation gaps remain below.
- Gemini grounding metadata is now forwarded to enrichment results. Display names are used in more form fields, the About dialog is connected, and the theme default has changed.
